## 四、写这份声明时，必须包含的要素

不管是发在哪个平台，下面几条**最好都写上**。省略哪一条都可能引来误解：

| 要素 | 为什么必须有 |
| --- | --- |
| **非商业 + 无隶属关系** | 用了游戏 IP 和美术风格，不写清楚容易被当成官方产品 |
| **不含美术素材** | 否则别人会以为你在分发鹰角的图，这是真实的侵权风险 |
| **不含游戏内文本** | 藏品名称/效果/说明同样是游戏内容，照抄会构成另一个层面的侵权 |
| **名单已脱敏** | 保护参与者的隐私，也向读者说明你是在意这件事的 |
| **票数不是严肃计票** | 这是最容易被误解的一条。写在仓库里（`SECURITY.md`）还不够，**公告里也要说** |
| **许可类型** | 让别人知道你授权了什么、没授权什么 |
| **素材与文本归属** | 明确「美术资源与游戏内文本版权归鹰角网络」 |

## 五、⚠️ 不要写的说法

这几句话很诱人，但**都不成立**，写了会给自己找麻烦：

| ❌ 不要写 | 为什么不行 |
| --- | --- |
| 「应援系统防刷票，票数公正」 | 不成立。脚本换 deviceId 就能无限投票，`SECURITY.md` 里写明了 |
| 「严格保护用户隐私，不采集任何数据」 | 过绝对了。有 `device_id`、昵称落库，云平台还有访问日志。应该说"不采集身份信息" |
| 「完全匿名，无法追溯」 | 排行榜昵称是你自己填的，且是公开的 |
| 「官方认证 / 官方合作」 | 没有这回事 |
| 「代码全部原创」 | 设计语言参考了游戏实机规范；如果用了任何开源代码要如实列出（本仓库没有运行时依赖，所以这条其实很轻） |
| 「已通过安全审计」 | 除非真的找第三方审过，否则只能写"做了哪些防护" |

## 六、如果想更稳妥一点

按代价从低到高：

1. **在仓库首页放一个醒目的免责声明区块**（`DISCLAIMER.md` 已经在仓库根目录了，
   README 里也有链接）。
2. **给美术素材与游戏内文本各写一段说明**，明确"需要自行准备、自行承担合法来源责任"。
   `web/assets/README.md` 已经写了。
3. **公告里主动提一句"票数可刷"**。主动说比被人指出来好得多，
   而且这也直接影响别人怎么使用你的榜单。
4. 如果顾虑较大，可以在 `web/index.html` 的应援按钮附近加一行小字：
   「票数用于表达人气倾向，非正式计票」。改动很小，
   但能把「用户以为这是投票」这个误解从源头掐掉。
